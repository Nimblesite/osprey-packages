# UX audit — browse, search, package list, package detail (UxPiBrowse)

Target: https://packages.ospreylang.dev/ (+ mirror https://nimblesite.github.io/osprey-packages/, API https://packages-api.ospreylang.dev/v1/packages).
Viewports: 1440×900 (desktop), 1024×768 (tablet), 390×844 (mobile). Chromium via Playwright; scripts and screenshots in `/tmp/ux-UxPiBrowse/`.

Method note: the **live catalog is empty** (`GET /v1/packages` → `{"packages":[]}`) and Cloudflare 308-redirects every `/packages/*`, `/publishers/*`, `/tags/*` route to `/package`, so **no package, publisher or tag page is reachable on production at all**. Findings marked *(fixture)* were obtained by intercepting the API response in the browser with a validated 8-package catalog and serving the `/package` shell for those routes (Playwright `route.fulfill`), which exercises the exact production WASM renderer (`site.702f2adc8327.wasm` + `catalog.8da87e406700.mjs`).

## Home page (`/`)

- **[critical] Live registry is empty.** `GET https://packages-api.ospreylang.dev/v1/packages` returns `{"packages":[]}` (CF cache HIT, 4 h max-age), so every viewport shows the hero, a search box and then "No packages published yet." (repro: open `/` at 1440/1024/390). `@osprey/json` is documented on ospreylang.dev but is not listed. → A visitor expects the registry to list the published `@osprey/*` packages; an empty production registry should at minimum link to the publishing guide and the upload page.
- **[major] "No packages published yet." is a dead end.** (1440/1024/390, below the "By publisher / By tag" chips.) One sentence, no explanation, no "Upload a package" or "Publishing guide" link, no retry. → An empty state should say why, and offer the next action (publish, read the guide, check status).
- **[major] Header navigation on desktop and tablet has only "Upload a package".** (1440 and 1024: `.prose-desktop-nav` has one link; the `Menu` details is `display:none`.) "Browse packages", "By publisher", "By tag" exist only inside the mobile menu. On any inner page the only way back to the list is the logo. → Desktop/tablet header should expose Browse / Publishers / Tags / Upload (and Sign in).
- **[major] CSP blocks the Cloudflare Insights beacon on every page load.** Console: `Loading the script 'https://static.cloudflareinsights.com/beacon.min.js/…' violates the following Content Security Policy directive: "script-src 'self' 'wasm-unsafe-eval'"` + a failed `csp` request, on `/`, `/package`, `/upload/`, every viewport. → No console errors on a production page; either allow the beacon or stop injecting it.
- **[minor] "By publisher" and "By tag" chips are broken links on production.** Both go 308 → `/package` → "The registry could not load this page." (see Navigation section). Clicking either from the home page leaves the visitor on an error page with no way back except the logo.
- **[minor] No skip link.** (keyboard, 1440) First Tab lands on the logo link, then Upload, then the search field; the `<main>` has no `id`/`tabindex`. → "Skip to content" as the first focusable element.
- **[minor] No meta description, Open Graph/Twitter tags, or canonical.** `<head>` has only `<title>Osprey Packages</title>` + viewport + icon. → Shared links should show a description/preview; add `<link rel="canonical">`.
- **[minor] robots.txt is Cloudflare's default content-signal boilerplate; `/sitemap.xml` and `/manifest.webmanifest` are 404.** → A registry that wants to be indexed should declare `Sitemap:` and ship one; add a webmanifest for installability if that is a goal.
- **[minor] Footer offers exactly one link (ospreylang.dev).** (all pages, all viewports) No Docs, Package guide, Publishing guide, API, GitHub, terms/privacy. The two guide pages that do exist (`/guide/`, `/publishing/`) are unreachable from any navigation. → Footer should carry the site map.
- **[minor] Mobile hero artwork glitch.** (390 only) The triangle pattern renders as a ~9 px strip peeking above the hero card's top edge above the rounded corners; inside the card it is a thin strip, not artwork. → Artwork should be clipped to the card or hidden at narrow widths.
- **[minor] Search box: pressing Escape in the `type=search` field clears the text but the URL stays `?q=ledger` and the results stay filtered** *(fixture)* (1440, type "ledger", Enter, Escape). → Clearing the field should reset the query (or at least the Search button should be the only way to apply — then the stale URL should not persist).
- **[minor] Search input lacks `enterkeyhint="search"`, `inputmode="search"` and `autocomplete="off"`.** (390) Mobile keyboards show a generic "go"/"return" key; and Chromium's form-state restoration on Back is what causes the Back-button bug below. → `enterkeyhint="search"`, `autocomplete="off"`.
- **[nit] Decorative `<img alt="">` elements are not `aria-hidden="true"`.** (`registry-mark.svg`, `osprey-mark.svg`; harmless today, brittle if alt text is ever added.)
- **[nit] Hero copy repeats the H1 and the page `<title>` verbatim ("Osprey Packages") and promises "download the source for a specific release" while nothing is downloadable.**

## Search box and search results *(fixture, 8-package catalog)*

- **[major] Browser Back after a second search shows inconsistent state.** Repro (1440): load `/?q=widgets` (1 result), type "finch", Enter (2 results, URL `?q=finch`), press Back → URL is `/?q=widgets` but the search box still contains "finch" and the results are finch's (2). The adapter (`registry-catalog.mjs`) writes the URL query into the field, Chromium then restores the typed form value over it, and the renderer is fed `field.value` instead of the URL. → URL, box and results must agree; render from `location.search`, set `autocomplete="off"`.
- **[major] Every search is a full page reload with no focus or announcement management.** Repro (1440): type "json", Enter → document reloads, `document.activeElement` is `BODY`, `scrollY` resets to 0, the H2 stays "Browse packages", `#catalog-status` (the only live region) is emptied. Screen-reader and keyboard users hear nothing and restart Tabbing from the logo. → Live filtering (the catalog is already client-side) or, at minimum, move focus to a "N results for 'json'" heading and announce via the live region.
- **[minor] No result count, no query echo, no highlighting.** Results for "json" are two cards under the unchanged "Browse packages" heading; the matched text is not emphasised. → "2 results for 'json'" (live region) with `<mark>` on matches.
- **[minor] Matching is naive case-insensitive substring over key + summary only.** "osi" → "No matching packages." (no prefix match on `@osprey`), "MIT" → 0 (licence not searchable), "Atlas Engineering" → 0 (publisher name not searchable), "json parser" → 0 ("parsing" ≠ "parser", no tokenisation). → Prefix/fuzzy match on name and scope; search publisher names, tags and licence; OR-fallback or "did you mean".
- **[minor] "No matching packages." is a bare dead end.** (1440, "zzzz") No query echo, no "Clear search" link, no suggestions, the box keeps the text. → Echo the query, offer to clear, suggest close matches.
- **[minor] Whitespace-only query is accepted and applied.** Repro: type three spaces, Enter → URL `/?q=+++`, box shows spaces, all 8 results. → Trim; treat blank as "no query".
- **[minor] Typing does nothing until Enter/Search.** (1440) With 8 packages already loaded, typing "ledger" leaves 8 cards for the whole keystroke sequence. → Filter as you type.
- **[minor] The search form exists only on `/`.** Package, publisher, tag and error pages have no search box and no header search. → Persistent header search.
- **[nit] Deep link `/?q=widgets` prefills and filters correctly; reload keeps results (works).** Forward after Back is consistent; only Back is broken.

## Package list cards *(fixture)*

- **[minor] Only the 23 px-tall title text is a link; the rest of the card is inert.** (1440: `a` is 132–216×23 px; mobile same height.) → Whole card clickable, or ≥44 px target.
- **[minor] Cards carry no version, publisher, release date, tags or install snippet.** Just key, summary, licence chip, warning bullets. A registry list is scanned for "is this the right `util`, who maintains it, is it current". → Latest version, publisher, date, tags, copyable `osprey add @scope/name`.
- **[minor] Security warnings are rendered as unlabelled bullets under the licence chip.** `@atlas/widgets` shows "• File access" with no heading — reads as a feature tag; only `aria-label="Security warnings"` on the `<ul>` hints at it. Every clean card repeats "No known security warnings." → A visible "Security warnings" label and a count/severity; drop the boilerplate or use a quiet "No known warnings" badge.
- **[minor] Licence chip has `aria-label="License"` but no visible label; "MIT OR Apache-2.0" and "LicenseRef-Proprietary" overflow the pill visually.** (1440, cards 5–7) → "License: MIT" with a short display for long expressions.
- **[minor] Card top-border colour (green / purple / orange) has no legend or semantics.** `@osprey/json` green, `@osprey/unit-test` purple, `@atlas/widgets` orange, `@atlas/util` green — unrelated to warnings or licence; reads like a status. → Remove or document the colour coding.
- **[minor] Long summaries are not clamped and rows stretch to the tallest card.** (1440) `@finch/ledger` card is 551 px tall with a 600-character summary; neighbours in the same row have 150–220 px of blank space. → 2–3 line clamp with "more" on the detail page; align-items: start.
- **[minor] Long keys wrap to five underlined monospace lines and dominate the card.** (`@long-scope-name-thirty-nine-chars-exact/cli-tool-with-a-very-long-name-for-layout-testing-123`, 1440 + 390) → Truncate the middle / clamp to two lines.
- **[nit] `#results` is a bare `<div>` of `<article>`s — no list semantics, so assistive tech never hears "8 packages".**

## Package detail pages (`/packages/<key>/`) *(fixture via `/package` shell)*

- **[major] Nothing tells a visitor how to use the package.** (all viewports) The page has: key, summary, release list (version, Download, licence chip, publisher, digest, collapsed notices), and an aside with licence, attribution link, warnings, tags. There is no install/dependency snippet (e.g. `osprey add @osprey/json`), no repository/homepage/documentation links, no published dates, no "Latest" marker, no release notes/changelog, no file list or archive size, no dependencies. → A registry package page's first job is "how do I depend on this".
- **[major] `<title>` is "Package · Osprey Packages" for every package.** The H1 has the key but the title never does; tabs, history and bookmarks for `@osprey/json`, `@atlas/util`, … are identical. → Title = `@osprey/json · Osprey Packages` (set after render).
- **[major] Downloads get the generic filename `osprey-source.json`.** The download link points at `packages-content.ospreylang.dev/v1/releases/<digest>/source`; the API replies `Content-Disposition: attachment; filename="osprey-source.json"` (`src/manager/api/lib/hosted_service.osp:274`), for every package and release. Repro *(fixture)*: click "Download e2.r1" → Playwright download `suggestedFilename() === "osprey-source.json"`. Two downloads collide as "osprey-source (1).json"; the format (a JSON source bundle, not a tarball) is not stated anywhere on the page. → `osprey-json-e2.r1.source.json`, state the format and size next to the button.
- **[major] No search on package pages, and the licence/warnings/tags aside is last in DOM order.** (all viewports) The search form is only on `/`. On desktop the aside is a right column but keyboard/reader order is: logo → Upload → ← Packages → every release link → aside. On mobile the aside renders below every release, so a user checking the licence or security warnings scrolls past all releases first. → Header search; aside (or a summary) before the release list.
- **[minor] Licence is an unlabelled chip-link that opens raw `text/plain` in the same tab.** Click "MIT" under "Download e2.r1" → `…/license` → `text/plain; charset=utf-8` page ("LICENSE\n\nMIT License…") with no site chrome and no link back; in the aside "License / MIT" is a non-link `<span>`, so the same information is a link in one place and not in the other. `e1.r1` shows Apache-2.0 while e2.r1/e1.r3 are MIT, with no note that older releases differ. → "License: MIT" labelled, opened in a new tab or an in-page panel; consistent link behaviour; flag per-release licence changes.
- **[minor] The 71-character digest is shown unlabelled in 13.6 px code with no copy control and no verification context.** (1440: `sha256:e94c…` 660 px wide; 390: wraps mid-hash over two lines.) "Package integrity is the product", yet nothing says "source digest — verify your download against this" and there is no copy button. → Label it, add a copy button, show the checksum next to the download.
- **[minor] "Tags: None" for packages whose keywords are not popular.** `@border/util` has keywords `util, helpers, files`, `@finch/ledger` has four — both render "Tags / None" because the page only shows tags shared by ≥5 packages. → Show the package's own keywords; optionally link only the popular ones.
- **[minor] "Published by" links to `/publishers/<raw-uuid>/`.** The URL exposes `11111111-1111-4111-8111-111111111111`; the publisher page is a name, "Published releases", then each card followed by a redundant credit list of the same links (`/packages/@osprey/json/#e2.r1`). No profile, handle, website or contact. → Human URL (`/publishers/osprey/`), a real profile header, one list of releases.
- **[minor] Release identifiers `e2.r1`, `e1.r3` are never explained and the list has no "Latest" badge.** *(fixture)* No epoch/compatibility explanation, no dates beside "Published by", no ordering cue. → "Latest" marker on the first release, date, and a one-line explanation of epoch.release.
- **[minor] Renderer preserves API order; it does not sort releases.** Repro *(fixture)*: reverse the release array → page lists `e1.r1, e1.r3, e2.r1` oldest first with no indication. → Sort newest-first in the renderer.
- **[minor] "Notices and attribution" disclosures are 21 px-tall `<summary>` rows with no hover affordance.** (`▶ NOTICE.md`, `▶ THIRD_PARTY_NOTICES.txt`, collapsed by default; `@atlas/util` has nine of them.) The aside's "Attribution → Notices and attribution" is an 18 px in-page link to `#e2.r1-notices`. → Bigger rows, visible file names + sizes, "Copy attribution" option.
- **[minor] Unknown package renders "← Packages / Package not found" with HTTP 200 and the generic title.** *(fixture)* `/packages/@osprey/nope/` → H1 "Package not found", no search suggestion, status 200. → 404 status, "Did you mean…", search box.
- **[minor] Mobile touch targets under 44 px.** (390) Download buttons 41 px, publisher links 18 px, "Notices and attribution" 18 px, tag chip 26 px, "← Packages" 25 px. → Pad to ≥44 px.
- **[minor] Aside is a loud lavender card — the same colour as the "By publisher / By tag" chips — and its H2s ("Package details", "Security warnings", "Tags") read as one block although they are siblings of "Releases".** (1440) The visual weight competes with the release list. → Neutral aside; nest warnings/tags under Package details or separate them visually.
- **[minor] Heading levels skip: H1 key, H2 Releases, H3 version, H4 "Notices and attribution", then H2 Package details / Security warnings / Tags.** Fine for AT but the H4 is a label for a disclosure group, not a section.
- **[nit] "← Packages" uses the "←" character, announced as "leftwards arrow"; the link box is 1094 px wide × 25 px tall.**
- **[nit] Hash `#e2.r1` scrolls correctly (432 px) but focus stays on `BODY`; `#e1.r1-notices`/`#nope` silently do nothing.**

## Releases, downloads, licences, notices — error handling *(fixture)*

- **[major] `Retry-After` is never surfaced: the API sends no `Access-Control-Expose-Headers`.** `registry-catalog.mjs` reads `response.headers.get('Retry-After')` to print "Please retry in N seconds", but for a cross-origin fetch only CORS-safelisted headers are readable, and `GET https://packages-api.ospreylang.dev/v1/packages` (with `Origin: https://packages.ospreylang.dev`) returns only `access-control-allow-origin` and `access-control-allow-credentials`. Repro *(fixture)*: respond 503 + `Retry-After: 30` → message is "The package catalog is temporarily busy. Please retry in a moment." → `Access-Control-Expose-Headers: Retry-After` on the API.
- **[major] A slow API leaves "Loading packages…" on screen for 10 s, then a dead-end error.** Repro *(fixture)*: delay the API 11 s → at 5 s still "Loading packages…" (no spinner, no skeleton), at ~10 s `AbortSignal.timeout` fires → "The public catalog is unavailable."; no Retry button, copy never says "Reload"; on a package page the loading copy is still "Loading packages…". → Skeleton/spinner, "Taking longer than usual", a Retry button, page-specific copy.
- **[minor] One invalid catalog entry blanks the entire site with a misleading message.** Repro *(fixture)*: `{packages:[valid, {key:"@x/y"}]}` → "The public catalog is unavailable." on `/` and "The registry could not load this page." on detail. It is not unavailable, it is invalid. → "The registry returned data this site cannot display" + status link; ideally drop the bad entry.
- **[minor] Four different phrasings for failures.** "No packages published yet." / "The public catalog is unavailable." / "The registry could not load this page." / "Page not found." / "Too many requests." — same failure, different words per page. Every failure is HTTP 200 and the detail failures have no `<h1>` (just a sentence in a 300 px hero). → One error component with heading, reason, Retry and "Browse packages".
- **[minor] No-JS / blocked-script states disagree between builds.** Live HTML with JavaScript disabled: search box and button are enabled, status reads "Loading packages…" forever, no `<noscript>`, submitting the form reloads to the same text. Mirror build disables both and says "The public catalog is unavailable.". Blocking `*.wasm` or `wasi.*.mjs` on live correctly yields "The public catalog is unavailable." → Disable the form until the renderer is live; add `<noscript>` guidance.
- **[minor] Download and licence links have no `target`/`rel`; a failing content host shows raw `application/problem+json`.** `curl …/v1/releases/<unknown>/source` → `{"code":"catalog.unknown-release","status":404}` as JSON; the licence endpoint returns `release.license-unavailable` JSON when a release has no licence file. A user who bookmarked a download sees a JSON blob. → Human problem page or an in-site error with a link back.

## Navigation and routes (live, all viewports)

- **[critical] Every browse sub-route is 308-redirected to `/package`, dropping the path.** `curl -I`: `/publishers/` → 308 `location: /package`; `/tags/` → 308; `/publishers/<uuid>/` → 308; `/tags/json/` → 308; `/packages/@osprey/json/` → 308; `/packages/anything/` → 308; `/packages/?q=1` → 308 `/package?q=1`. In the browser each lands on the "Package · Osprey Packages" shell with "The registry could not load this page." (HTTP 200). Repro: from `/` click "By publisher" or "By tag", or open any `/packages/…/` URL from search results. → These routes must serve the shell (rewrite, 200) so the client renderer sees the path; a 308 that discards the path makes the whole browse section of the site unreachable.
- **[major] The `/package` error page is a dead end.** (1440) Header + a 300 px dark hero containing one sentence + footer; no `<h1>`, no "Browse packages", no Retry, no explanation, HTTP 200, title "Package · Osprey Packages". → 404 page with heading, reason, links.
- **[major] `/signin/`, `/register/`, `/recover/` are 404 "Page not found" on production** (the auth screens in `site/src/main.osp` are not deployed) — noted for the account audit; from a browse perspective the header has no Sign in at all.
- **[minor] Trailing-slash handling is inconsistent.** `/upload` → 308 `/upload/` (200); `/package/` → 308 `/package`; `/packages` → 404; `/publishers` → 404; `/PACKAGES/X/` → 404 (case-sensitive). → One rule, applied everywhere.
- **[minor] Mobile menu (`<details>`) does not close on Escape or on tapping outside.** Repro (390): open "Menu", press Escape → still open; tap the hero at (200,600) → still open; only the summary toggles it. The dropdown (192×196 px, `position:absolute`, `z-index:auto`, no scrim/shadow) overlaps the hero; the current-page item "Browse packages" is greyed with no `aria-current="page"`. Summary and links are 44/46 px (good). → Close on Esc/outside/route change; `aria-current`; a proper sheet or nav bar.
- **[minor] Focus lands on `BODY` after every navigation and after the menu; no route announces the new page.**
- **[nit] Both header navs are labelled `aria-label="Primary"` (one hidden via CSS, so no duplicate landmark today, but fragile).**
- **[nit] `/package` shell keeps `data-missing="Page not found."` while the renderer's not-found state is "Package not found" — two spellings of the same state.**

## Mirror (https://nimblesite.github.io/osprey-packages/)

- **[major] The mirror is a dead, different build.** (all viewports) Static HTML has `disabled` on the search input and Search button, status "The public catalog is unavailable.", no adapter script, a different stylesheet hash (`registry.e5b3f1a50ee3.css` vs live `registry.f3c439e00338.css`). `/publishers/`, `/tags/`, `/packages/x/`, `/signin/` → GitHub Pages 404 "Page not found"; `/upload/`, `/guide/`, `/publishing/` → 200 (stale copies). GitHub Pages sends no CSP, no `X-Content-Type-Options`, no `Referrer-Policy`, no `Permissions-Policy`; the API rejects the mirror origin with 403 (CORS). `?q=json` just reloads the unavailable message. → Either deploy the same build with the API allowing the mirror origin, or take the mirror down / redirect it to the live site.
- **[minor] Mirror 404 page has no link back to the mirror root** ("Browse packages" points to `/` of github.io, not `/osprey-packages/`).
