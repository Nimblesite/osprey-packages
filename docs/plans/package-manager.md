# Package Registry and Manager

> **ONE WAY TO RELEASE.** A package version reaches the public registry one way only: a publisher signs an intent for a commit in the package's bound GitHub repository, and the registry fetches, freezes, scans and publishes that commit itself ([`[PACKAGE-HOSTED-PUBLISH-FLOW]`](../specs/ecosystem/PackageRegistryDeploymentAndOwnership.md#releasing-from-a-github-repository-package-hosted-publish-flow)). There is no upload, no second path, no operator shortcut and no test-only bypass. Anything else that puts a version in the catalog is a defect.

Goal: deliver the registry this plan's contracts fix: a local engine with canonical digests, locks and a complete resolver; a verifiable public registry with TUF trust, hosted ownership behind the same Osprey API, hermetic publication and fair discovery; and a hardened general-availability launch. The folder registry, verified fetch/install, deterministic resolver, locks, overlays and folder publish already run (`make _registry-test`, CI job `test`: client suites under GC, API and WASM suites under ARC).

Contract: [Package Management](../specs/ecosystem/PackageManagement.md), [Trust and Discovery](../specs/ecosystem/PackageRegistryTrustAndDiscovery.md), [Domain Model](../specs/ecosystem/PackageDomainModel.md), [Domain Invariants](../specs/ecosystem/PackageDomainInvariants.md), [Evidence and Fair Discovery](../specs/ecosystem/PackageEvidenceAndDiscovery.md), [Python-Flavor Ports](https://github.com/Nimblesite/osprey/blob/main/docs/specs/ecosystem/0043-PythonFlavorPorts.md), [Deployment and Ownership](../specs/ecosystem/PackageRegistryDeploymentAndOwnership.md), [Organization Governance](../specs/ecosystem/OrganizationPackageGovernance.md)
